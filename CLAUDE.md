# CLAUDE.md

Guidance for AI coding assistants (and humans) working in this repository.

## Layout

- `backend/`: Spring Boot 3.5, Java 21, Maven wrapper. Package root `com.bankms`, layered `controller → service → repository` plus `dto`, `mapper`, `entity`, `security`, `exception`, `config`, `scheduler`, `audit`.
- `frontend/`: React 18 + Vite + TypeScript + Tailwind 4. `src/api` (TanStack Query hooks per portal), `src/pages/{auth,customer,staff,admin,shared}`, `src/components`.
- `docker-compose.yml`: MySQL 8.4, MailHog, backend, nginx frontend. `.env.example` lists every variable.
- `docs/interview-notes.md`: the reasoning behind the non-obvious decisions. Read it before changing money, locking, auth or jobs.
- Public demo: `vercel.json` (frontend + `/api` proxy), `render.yaml` (API, `prod,demo` profiles), `application-demo.yml`. See `docs/deployment.md`. The demo profile wipes and reseeds the database on every start, so never point it at real data.

## Commands

```bash
cd backend && ./mvnw test                 # unit tests (no DB/Docker)
cd backend && ./mvnw verify               # + Testcontainers integration tests (needs Docker, or IT_DB_URL)
cd backend && ./mvnw spring-boot:run      # dev profile: Flyway + demo seed, reads ../.env
cd backend && python scripts/generate_seed.py   # regenerate db/seed/V2_1__demo_data.sql
cd frontend && npm run dev | npm run lint | npm run typecheck | npm run build
docker compose up --build                 # whole stack on :3000 / :8080 / :8025
```

## Rules that keep the bank correct

1. **Money is `BigDecimal` scale 2** (`util/Money`). Never `double`/`float`, not even in DTOs or tests. Columns are `DECIMAL(19,2)`.
2. **Every balance change goes through `LedgerService`**: `lock()`/`lockInOrder()` first (ascending id, prevents deadlocks), validate against the locked row, then `post()`. Never set `Account.balance` directly outside it.
3. **Money-moving endpoints require `Idempotency-Key`** and follow the pattern in `TransactionService` → `TransferService`: reserve the key as the first write, `idempotency.complete(...)` before returning.
4. **Money-moving transactions use READ_COMMITTED** (see the `TransferService` javadoc). Keep it if you add one.
5. **Scheduled jobs process one item per transaction** (`TransactionTemplate`), lock the item row first, and must be safe to run twice.
6. **Never expose entities**: request/response records in `dto`, MapStruct mappers (`unmappedTargetPolicy=ERROR`, so new fields must be mapped or ignored explicitly).
7. **Errors** are thrown as `BankException(ErrorCode, message)`. Add new codes to `ErrorCode`; messages are user-facing, so write them in plain language.
8. **Authorisation** lives in two places: URL rules in `SecurityConfig` and `@PreAuthorize` on controllers. Customer data is scoped by the authenticated user, never by an id the client sends, unless guarded by `@accountSecurity`.
9. **Sensitive actions get `@Audited`** on the service method; keep the aspect ordered outside `@Transactional`.
10. **Schema changes are new Flyway migrations** in `db/migration` (never edit an applied one). Demo data lives in `db/seed` (dev profile only) and is generated by the script above.
11. **Time comes from the injected `Clock`** (`LocalDate.now(clock)` for business dates, `Instant.now(clock)` for timestamps).

## Frontend conventions

- The access token stays in memory (`lib/session.ts`); never persist it. `lib/api.ts` handles refresh.
- Forms: React Hook Form + Zod (`lib/schemas.ts` mirrors the server rules), with server `fieldErrors` mapped back via `applyFieldErrors`.
- Design tokens live in `src/index.css` (`@theme`). Violet (`stamp`) is reserved for status stamps; red/green only for debit/credit money. The chart palette in `components/charts/Charts.tsx` was validated for colour-vision deficiency; re-validate if you change it.
- Transaction lists use `<Passbook>`; statuses use `<Stamp>`.
